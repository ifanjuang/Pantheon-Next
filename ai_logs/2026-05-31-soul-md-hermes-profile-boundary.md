## Why the change was made

`SOUL.md` is useful as a pattern for stabilizing Hermes execution profiles.

The useful part is not theatrical persona design.

The useful part is execution predictability:

```text
identity posture
communication tone
uncertainty behavior
pushback behavior
capability-gap behavior
candidate-output discipline
evidence discipline
hard stops
```

This can make Hermes candidate outputs easier to review.

## Governance boundary

The pattern is explicitly limited to Hermes profile identity.

It does not create Pantheon authority.

It does not create a runtime.

It does not create a profile marketplace.

It does not install `SOUL.md`.

It does not modify Hermes runtime behavior.

It does not authorize tools.

It does not approve outputs.

It does not promote memory.

It does not define a Pantheon Role.

## Key doctrine preserved

```text
OpenWebUI exposes.
Hermes Agent executes.
Pantheon Next governs.
```

The new review preserves the distinction:

```text
Pantheon Role != Hermes Profile != SOUL-like identity layer
```

A SOUL-like file may shape how Hermes executes.

It must not alter what Hermes is authorized to do.

If a profile identity conflicts with the Task Contract, Context Pack, External Tools Policy, approvals, memory policy or `AGENTS.md`, the governance artifact wins.

## Risks and limitations

Main risks identified:

- persona theatre replacing professional discipline;
- role names becoming agent identities;
- profile confidence being mistaken for evidence confidence;
- a stable voice masking weak sources;
- profile preferences overriding Task Contract scope;
- a SOUL-like file becoming a hidden policy override.

The review mitigates those risks by classifying the pattern as `hermes_candidate_constraint`, not active Pantheon authority.
