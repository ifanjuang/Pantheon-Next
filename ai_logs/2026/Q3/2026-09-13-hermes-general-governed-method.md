# AI log — Hermes general governed method

Date: 2026-09-13
Status: repository implementation intervention — deployed and live semantic acceptance observed.

## Observation

The governed Hermes profile already had request intake, source routing and
activity projection, while the seven-movement Governed Method Standard remained
documented but non-implemented. The deployed Pantheon Policy MCP allowlist also
exposed consultation only even though the server already implements read-only
classification, preflight, candidate skeleton and Context Pack functions.

The visible Role outcome convention used `OK / réserve / blocage`, which
duplicated the more precise readiness vocabulary already owned by
`ROLE_SIGNALS.md`. A dossier-specific Floquet acceptance section also risked
making the general presentation adapter look like a project workflow.

## Change

- added the general `pantheon-governed-method` skill candidate around Frame,
  Admit, Qualify, Compose, Produce Candidate, Test and Status;
- made method selection condition-driven and limited normal composition to one
  primary method, one guardrail and one verification method;
- added a generic source-preflight receipt template that requires the actual
  binding, exact source opened, inspected locator, limitations and Context Pack
  validation result when applicable;
- exposed the six already-implemented read-only Pantheon Policy functions needed
  by the governed flow through the reviewed MCP allowlist;
- installed `external-commitment-guard` as a general guard for messages,
  documents, specifications, forms, publications and system actions;
- aligned visible outcomes with `ready`, `ready_with_limits`,
  `needs_revision`, `needs_user_input` and `blocked`;
- generalized the professional source-verification presentation and kept
  project/client identities out of the runtime method;
- added deterministic policy tests across a budget, an external message and a
  technical specification rather than encoding one object-specific workflow;
- reconciled the candidate Hermes qualification pin and attachment-boundary
  compatibility check with upstream Hermes Agent 0.21.2 (`v2026.9.11`).

## Boundary

The method is an external Hermes coordination skill, not a Pantheon workflow
engine. It invokes existing runtime skills and read-only policy functions; the
MCP does not execute work. The source receipt is a task-local trace and does not
validate truth, create Evidence, approve a result or promote memory.

```text
condition-driven composition != object-specific workflow
viewpoint != autonomous agent
source receipt != Evidence
readiness != approval
draft ready != external transmission authorized
```

The Hermes provider is not patched. Repository tests do not prove live model
routing, progressive WhatsApp presentation or production source retrieval;
those remain separate runtime acceptance observations.

## Live acceptance observation

The candidate skills, governed SOUL appendix and reviewed twelve-tool Pantheon
Policy MCP allowlist were installed into the live `pantheon-governed` profile on
Hermes Agent 0.21.2. The container was restarted and reported healthy gateway,
dashboard, storage, WhatsApp and API components. The Pantheon MCP connected and
exposed the selected tool set.

A generic CLI-profile prompt, deliberately naming no deliverable or business
domain, caused the model to classify the request, consult the Pantheon source
catalog and doctrine, avoid fabricating the source-dependent claim, limit the
visible projection to Athena, Hermes and Zeus, and return the canonical status
`ready_with_limits`. This validates one semantic path only; it is not yet a
representative routing corpus or a WhatsApp progressive-rendering acceptance.

The same prompt through the profile-prefixed Runs API did not expose MCP tools:
`GET /p/pantheon-governed/v1/toolsets` reported every API-server toolset as
disabled. That result is an observed platform boundary, not evidence that the
profile MCP or messaging gateway is unavailable. The API surface must therefore
not be used as a tool-routing acceptance fixture until its tool policy is
explicitly configured and reviewed.
