# Architect landing page rewrite

Date: 2026-06-15
Branch: `rewrite/architect-landing-copy`

## What changed

Rewrote `docs/index.html` as a public-facing landing page centered on architecture practice rather than generic AI-product positioning.

The rewrite emphasizes:

- Pantheon Next as a simple entry point for architecture agencies;
- “façonné par un architecte pour des architectes” as the main positioning signal;
- project coherence, design time, drawing time, product research and regulatory research;
- MAF / Ordre-style professional responsibility reflexes without claiming compliance or certification;
- concrete architecture situations: VISA, DAACT, PLU response, client programme changes, sketch validation, site-presence ambiguity;
- precise, sourced, reviewable notes rather than decorative AI answers;
- progressive adoption for agencies reluctant to use AI.

## Why

The previous landing copy was readable but still too generic and too close to SaaS / chatbot language. It did not sufficiently distinguish the architect’s work from simple maître d’œuvre / OPC task tracking. The user requested stronger architectural positioning while keeping the product easy to understand and useful.

## Doctrine alignment

This remains documentation / static HTML only.

No runtime, connector, workflow engine, provider router, scheduler, queue, approval engine, memory engine, OpenWebUI Function, Hermes skill, schema, test, operation file, Docker change or `.env` change is introduced.

The page keeps the governing distinction:

```text
The surface exposes.
The runtime executes.
Pantheon governs.
The architect decides.
```

## Limits

This is a landing page rewrite, not an implemented product feature.

The wording mentions MAF / Ordre reflexes as professional responsibility framing, not as formal endorsement, compliance certification or legal advice.
