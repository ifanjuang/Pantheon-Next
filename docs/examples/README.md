# Professional Examples

Status: fictional examples — educational support only.

These examples show how Pantheon Next can frame AI-assisted work on professional dossiers.

They are not governance doctrine.

They are not implementation.

They are not legal, medical, technical, accounting or professional advice.

They do not validate any output.

They do not prove that Pantheon prevents professional fault.

They illustrate a method:

```text
request
→ mission sheet
→ sources and scope
→ proof folder
→ candidate deliverable
→ human validation
→ scoped memory only if approved
```

Internal doctrine remains:

```text
OpenWebUI exposes.
Hermes Agent executes.
Pantheon Next governs.
```

## Status of sensitive examples

Legal and medical examples are draft use-case doctrines under elaboration.

They must be reviewed with the relevant professionals before being presented as stable doctrine.

Until then, they remain:

```text
fictional
illustrative
draft
non-prescriptive
non-advisory
```

## Reading rule

Each example should make visible:

- what the professional asked;
- which sources were allowed;
- which sources were excluded;
- what was assumed;
- what contradicted what;
- what stayed candidate;
- what required human validation;
- what could or could not become memory.

## Best first reading path

```text
1. architecture_devis_reprise/
2. regulatory_watch_conflict/
3. PRACTITIONER_HOOKS.md
```

The first case shows how Pantheon prevents a fluent AI draft from becoming a risky professional act.

The second case shows how Pantheon can flag that new external information may disturb active dossier assumptions without automatically rewriting those dossiers.

## Boundary

The examples may use Pantheon vocabulary such as `Task Contract`, `Evidence Pack`, `Memory Candidate`, `Governance College` or `User Decision Gate`.

They do not create a runtime.

They do not define schemas.

They do not authorize OpenWebUI, Hermes or any external model to perform real professional acts without human validation.
