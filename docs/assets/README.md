## Placement rule

Visual material stays in Pantheon Next when it explains governance, conformance or a non-executable interaction grammar.

Product cockpit screens, executable product renderers, synthetic project data and runtime scenarios belong in `ifanjuang/pantheon-mvp`.

A byte-matched or synthetic preview may remain only when it validates a separately hosted external template and is explicitly classified as preview rather than product ownership.

Superseded mockups are removed rather than migrated. Git history and `ai_logs/` preserve the trace.

See `../governance/NEXT_MVP_REPOSITORY_PLACEMENT.md` for the full boundary.

## Status rule

Every asset must visibly distinguish:

```text
implemented
implemented externally
partial / to verify
documented non-implemented
candidate
obsolete
voluntarily absent
```

A visible button or workflow must not imply execution unless the implementation and runtime binding are separately established.

## Public wording

The retired `pantheon-control/` path must be described as an orientation or external binding pointer, not as a Pantheon Next dashboard.

Preferred labels:

```text
External MVP cockpit demo
Orientation vers le cockpit MVP
Synthetic Hermes renderer preview
Governance-grammar prototype
```

Avoid unqualified claims such as `dashboard live`, `services en ligne`, `connexions actives` or `control plane opérationnel` without current evidence.

## Evidence and memory wording

```text
Hermes memory     -> runtime recall without authority
Knowledge         -> organized reference, not automatically true or approved
Evidence          -> scoped support deliberately admitted for a claim
Registre          -> governed durable record after required validation
```

Display does not create probative status.

## Anti-runtime reminder

This directory contains no runtime resources, deployment configuration, approval engine, scheduler, queue, provider router, installer, memory promotion engine or external-action component.
