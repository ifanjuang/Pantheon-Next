# Premisses Cachees

Status: active doctrine - shared rite.

## Intention

Expose implicit assumptions before planning, producing or deciding.

This rite prevents Pantheon from building a clean workflow on an unstable premise.

## Trigger conditions

Use this rite when:

- the user request contains an implied conclusion;
- roles disagree without knowing why;
- a solution feels obvious but the problem is unstable;
- scope, success criteria or authority are unclear;
- a Task Contract may hide a missing constraint;
- a candidate output depends on a preference, source or approval that has not been stated.

## Anti-triggers

Do not use this rite when:

- the request is explicit and low risk;
- assumptions do not affect the next output;
- a missing detail can be handled as a simple reserve;
- the work is purely stylistic and does not affect meaning, evidence, approval, memory or transmission.

## Roles called

- ATHENA extracts the structure.
- APOLLO clarifies terms and success criteria.
- THEMIS challenges fragile assumptions and approval implications.
- ARGOS identifies source assumptions when needed.
- ZEUS decides whether the Task Contract must be revised.

## Procedure

1. Extract the explicit request.
2. Extract implied assumptions.
3. Separate constraints from preferences.
4. Identify missing authority, source or approval.
5. Mark assumptions that affect delivery, evidence, memory or transmission.
6. Rewrite the problem in a narrower form.
7. Decide whether work can continue, continue with reserve, or require Task Contract revision.

## Outputs

- hidden assumptions;
- clarified terms;
- revised problem statement;
- source or authority gaps;
- scope warning;
- Task Contract revision note if needed;
- ZEUS status.

## Evidence Pack impact

If hidden assumptions affect the result, the Evidence Pack should record:

- assumption text;
- whether it was user-provided, inferred or unresolved;
- impact on output;
- impact on evidence;
- impact on approval;
- impact on memory;
- required follow-up.

The Evidence Pack must distinguish assumption from fact.

## User Decision Gate impact

Open a User Decision Gate when:

- an assumption changes the safe procedure;
- the user must choose between competing interpretations;
- a professional or external effect depends on an unstated premise;
- scope expansion would otherwise happen silently.

## Memory impact

This rite may propose a Memory Candidate only when the assumption is explicitly confirmed, scoped and useful for future governed work.

The rite must not promote Canonical Memory.

## Failure modes

- over-interrogating simple tasks;
- converting every missing preference into a blocker;
- treating inferred assumptions as facts;
- hiding assumptions in polished prose;
- broadening scope without explicit review.

## Forbidden drift

This rite must not become:

- user profiling;
- hidden preference memory;
- automatic scope expansion;
- runtime intent classifier;
- approval bypass;
- memory promotion pipeline.

## Final rule

A clean answer built on a hidden premise is still unsafe.
