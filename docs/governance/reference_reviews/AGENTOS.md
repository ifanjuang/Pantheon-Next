# AgentOS Reference Review

Status: external reference — candidate vocabulary only.

Date: 2026-06-01

AgentOS is a useful external runtime reference for Pantheon Next.

It is not a Pantheon architecture model.

It does not authorize runtime execution, generated tool use, automatic memory promotion, persona authority or autonomous approval inside Pantheon.

```text
OpenWebUI exposes.
Hermes Agent executes.
Pantheon Next governs.
```

## Accepted distillation

Pantheon may use AgentOS as a vocabulary source for:

- dynamic runtime capability candidates;
- runtime memory quality signals;
- claim-level evidence review;
- rejected runtime collapses;
- external runtime boundary analysis.

This is support vocabulary only.

It does not create a module, runtime, bridge, schema, OpenWebUI extension, Hermes skill, memory engine or approval engine.

## Rejected import

Pantheon must not import AgentOS as:

- runtime architecture;
- autonomous generated-capability system;
- memory promotion mechanism;
- approval mechanism;
- Pantheon Role model;
- source-of-truth system;
- hidden orchestration layer.

## Dynamic runtime capability candidates

A runtime may propose a capability.

Pantheon may govern whether that capability is eligible.

No generated capability is authorized by the fact of being generated.

Any generated code, schema, prompt or capability description remains candidate material until reviewed under Task Contract, Evidence Pack and approval rules.

## Runtime memory signals

Runtime memory signals may help prioritize review.

They cannot promote memory.

Allowed signals include:

- source confidence;
- recency or staleness;
- contradiction count;
- decay or review-after date;
- retrieval frequency;
- supersession risk.

A memory score is a review signal, not a Registre Probatoire entry.

Forgetting in a runtime store is not revocation of a Registre Probatoire entry.

Decay is not governance.

## Claim ledger

AgentOS-style claim checking is useful as a review aid when an output contains separable claims.

A claim ledger may classify claims as:

```text
supported
weak
unverified
contradicted
out_of_scope
```

A claim ledger makes review sharper.

It does not make the verifier sovereign.
