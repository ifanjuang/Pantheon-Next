## What it is

The paper frames autotelic AI as agency that can generate, revise or select its own objectives instead of merely executing externally supplied tasks.

For Pantheon Next, the useful import is not the metaphysical framing. The useful import is the governance risk: a system that proposes its own objectives can silently convert a generated intention into a task, memory, truth claim, approval path or external action unless the boundary is explicit.

This review records the concept as a support reference. It does not promote the paper to doctrine, create an agent model, add a runtime, define a scheduler, implement a workflow loop or authorize autonomous goal formation.

## Pantheon translation

The safe translation is:

```text
A module may generate an Intent Candidate.
Pantheon governs admissibility.
Only an approved intention may become a scoped task.
Execution remains external.
Memory, truth and external action are never self-authorized.
```

This reinforces the existing envelope:

```text
Task Contract in
-> module / skill / workflow
-> Result Candidate + Evidence Pack Candidate out
```

Autotelic systems add one more candidate class before task execution:

```text
Runtime observation
-> Intent Candidate
-> admissibility review
-> Task Contract if accepted
-> external execution if authorized
-> Result Candidate + Evidence Pack Candidate
```

## Admissibility questions

Before an intention generated by a runtime, workflow, skill or module can become a task, the review must ask:

```text
Does it create or alter a truth claim?
Does it propose memory creation, reuse or promotion?
Does it change status, legitimacy, approval or scope?
Does it trigger an external action?
Does it touch a professional responsibility boundary?
Does it require evidence the runtime does not have?
Does it rely on an unreviewed self-model, role assumption or boundary assumption?
```

If the answer is yes, the output remains candidate-only until a visible gate qualifies it.

## Boundary with Hermes and OpenWebUI

Hermes may generate Intent Candidates while executing under a Task Contract. OpenWebUI may display those candidates and capture human decisions.

Neither Hermes nor OpenWebUI may convert an Intent Candidate into:

```text
approved task;
canonical memory;
truth final;
approval final;
external action;
repository mutation authority;
professional validation.
```

## Relation to the dieux dialogue log

A dieux dialogue log should not be only narrative. It should expose candidate state transitions.

Minimal useful sequence:

```text
Hermes observes a gap.
Hermes proposes an Intent Candidate.
Athena checks proof, scope and doctrine tension.
Hephaistos may propose a technical artifact candidate.
Zeus qualifies status or asks for arbitration.
The human decides any external or canonical effect.
```

The log is therefore a governance-readable intent and arbitration trace, not theatrical commentary.
