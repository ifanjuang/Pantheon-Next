Understand · no prerequisites

What actually happens when you ask an AI to do something?

On screen, a question goes in and an answer comes out. Under the hood, several things may search, read, remember, act and hand work to one another. Here is the map in normal language.

Pantheon does not invent these mechanisms.

It organizes them when they enter work where sources, versions, responsibilities and decisions matter.

The map before the details

In two minutes.

You can understand the essentials through a few simple roles. The technical names can come later.

01 · Produce

The model

It works with what it is given.

It can write, analyze, compare or reason. It does not automatically possess your whole project file.

02 · Supply

Context

What you put on its desk.

The question, instructions, document passages, search results or useful memories: this is the material available for the task.

03 · Retrieve

RAG

Search before answering.

The system retrieves a few useful passages from your sources and adds them to the model’s context.

04 · Continue

Memory

What is kept for later.

It avoids starting from zero, but a remembered item still needs to be understood in its original context.

05 · Do

The executor

The part that carries out the mission.

It can mobilize a model, tools and reusable know-how, work through several steps and return a result.

06 · Frame

Pantheon

It keeps the dossier frame readable.

Mission, scope, sources, capabilities, provenance, statuses, evidence and decisions stay visible.

1 · Know

How does AI find what it needs?

A model may be powerful, but it does not automatically read your hard drive, email and 300-page dossier. The right information has to be prepared and retrieved.

Context

The working desk.

Too little information and a key piece may be missing. Too much and the desk fills with noise. Good context contains what the mission actually needs.

Tokens

The small change of context.

Models split text into small units. They cannot look at an infinite amount at once, which is why useful passages are selected instead of sending an entire library with every request.

The chunk

A piece with its address attached.

A long document is split into searchable passages. A good system keeps the original document, page, section and location information with each piece.

The embedding

A mathematical map of meaning.

It helps bring together two passages that discuss the same idea even when they use different words.

Question
↓

Answer
Keyword search, semantic search, hybrid search: why use several methods?

A clause number or exact name is easy to retrieve by words. A different formulation expressing the same idea may be easier to retrieve by semantic proximity. Hybrid retrieval combines those strengths and ranks candidate passages.

The score organizes retrieval. It does not make the top result true.

What would RAG do in LIA21?

The ventilation question may retrieve a specification, a meeting note and an inspection record. Those passages can be passed to the model to prepare a reply. Their dates, versions and actual role in the dossier still need to be understood.

2 · Organize

Good memory starts by not mixing everything together.

A single giant memory sounds attractive. In professional work, it is also a very good way to make an old assumption reappear in the wrong place.

Three working-memory spaces

A

Agency

What may help elsewhere.

Methods, references, templates, generalizable lessons and know-how that should outlive a particular project.

P

Projects

What belongs to one dossier.

Notes, meetings, hypotheses, context, drafts and reasoning specific to LIA21, SOL14 or another project.

S

Sandbox

The laboratory.

Tests, synthetic data, new models, new versions and integration experiments. What happens here must not come back as if it were a real client-project memory.

These are working-memory domains. They do not replace the professional status of an item. A useful note may remain a note; an important decision should be traceable to its source and context.

Classification: from broad to precise

SPACE        Projects
  ↓
DOSSIER      LIA21
  ↓
CONTEXT      Site / Meeting / Ventilation
  ↓
SOURCE       LIA21_CR_014.md
  ↓
PASSAGE      retrieved chunk

This makes it possible to ask “what do we know about ventilation?” without silently letting SOL14 memories leak into LIA21.

Versions: the right information at the right time

Keep the history

An older version does not need to vanish. It may explain why a decision was made at a certain point in time.

Know which one applies now

The system should also show which revision is current, which one was superseded and which version a retrieved passage came from.

Why Markdown?

Markdown, usually stored as .md, is just plain text with a few simple marks for headings, lists and links.

# LIA21 — 14 August meeting

## Ventilation
The inspection still needs confirmation.

- expected source
- contractor reply pending

The same file stays easy to read for a person, an editor and an AI. It is lightweight, easy to compare between versions, easy to search and does not need a proprietary format to remain understandable.

Markdown does not replace the original. A received PDF remains the received PDF. Markdown can be a convenient working representation for reading, classifying, comparing and searching its content.

Why not create a separate memory database for every project?

A project is a working context, not automatically a separate trust boundary. Strict folders and tags can keep project recall bounded while avoiding unnecessary fragmentation of retrieval, archiving and cross-project comparison.

What about conversation memory?

It can make an assistant more comfortable by keeping useful continuity. For governed tasks, that memory can be restricted or disabled so that the result rests on explicit context rather than invisible recall.

3 · Act

When AI moves from “answer” to “do”.

Once a system can open a file, search the Web, call an API or modify something, the question is no longer only what it knows. We also need to understand how the work gets executed.

The tool

An action capability.

Read a file, call a service, search, calculate, export or send. A tool gives the system something concrete it can do.

The skill

Knowing how to do it.

The tool can open a PDF. The skill explains how to review the dossier, what to check and how to present the result.

The agent

Receive an objective and work toward it.

It can observe, choose an action, use a tool, inspect the outcome and continue until the mission is complete.

The executor

The part that actually performs the mission.

This may be an agent runtime or external execution service. Pantheon should be able to replace it without changing its own responsibility.

The run

One concrete execution.

Running the same task tomorrow creates a new run, with its own date, events, tool calls and returned result.

The workflow

The recipe.

It describes a repeatable sequence. The engine that actually executes that recipe is a separate responsibility.

Mission
↓
Executor
↓
Models · skills · tools
↓
Run
↓
Result
API, connector, MCP: what are they for?

An API lets two software systems communicate. A connector adapts a particular service. MCP provides a standardized way to expose tools and resources to AI systems. These mechanisms make connection easier; permission to use a capability in a mission remains a separate question.

Task, session and run: what is the simple difference?

The task describes what must be accomplished. The session keeps continuity across exchanges. The run is one concrete execution. A session can therefore include several tasks and several runs.

4 · Count

A plausible answer is only the start of the question.

Back to LIA21. The system finds a sentence saying the ventilation is compliant and prepares a reply for Mme. C. Before relying on it, we still need to understand what that sentence actually means in this dossier.

?
Which document? Which date? Which version? Who wrote it? Is it a declaration or an inspection? Is there a more recent piece?

This is where Pantheon becomes useful: not by redoing the model’s reasoning, but by keeping the mission and dossier path reviewable.

The mission sheet

What we ask, and how far it may go.

Objective, dossier, usable sources, allowed capabilities, expected result and the decisions that must remain human. In Pantheon’s technical documentation, this frame is notably expressed by the Task Contract.

The green light

This execution may start.

A well-defined mission may still need a check before launch. The technical documentation calls this step Execution Admission.

Provenance

Where did this statement come from?

Document, email, Web, memory, calculation, tool or person: preserving origin makes it possible to return to the actual material instead of keeping only the AI conclusion.

The candidate result

A proposal before a conclusion.

The runtime may have completed its work while the content still needs review before it becomes a professional position.

Evidence

What you can put on the table.

An item sufficiently qualified to support a claim or decision in the intended context, with provenance and limits visible.

The Probative Register

“Here is why we may rely on it.”

It keeps qualified assertions linked to their provenance. Its purpose differs from associative memory, which mainly helps recall.

Technology candidates

The roles stay stable. Products may change.

Naming a candidate shows how a function might be filled today. It does not make that product a mandatory Pantheon dependency.

Agent execution

Hermes Agent is currently studied as the main candidate for the external executor role: receive a bounded mission, mobilize models, skills and tools, then return the run result.

candidate · replaceable

Notes and workspace

Obsidian is a qualified candidate for local Markdown notes and human-readable organization. The files remain usable independently of the application.

workspace candidate / qualified in a bounded scope

Associative memory

Hindsight is the first currently qualified candidate for associative working memory derived from notes, with separated domains and bounded reads. It helps recall; it does not become the professional authority of the dossier.

working-memory candidate · bounded use

Memory alternative

TencentDB Agent Memory has been evaluated. The tested integration exposed failure-state consistency and identity-isolation issues, so activation is deferred for the current topology. It may be evaluated again if the situation changes.

evaluated · deferred

Document analysis

Docling is the preferred candidate for extracting document structure: headings, paragraphs, tables, reading order and source-linked derivatives. The candidate implementation already knows how to compile that kind of output into traceable units and chunks.

preferred candidate · runtime integration still to qualify

Data and privacy

Does everything have to go to the cloud?

No. The architecture can remain fully local.

Documents can stay on a computer or private server. Markdown notes can remain local files. Extraction, retrieval, associative memory, databases and even models can be operated locally when the selected candidates support it.

Cloud services remain possible when they bring a useful capability and their use is accepted. Web search, a hosted model or an external API obviously crosses the local boundary.

The principle is explicit choice: local, hybrid or cloud depending on the dossier and selected capabilities, without making a particular provider structurally mandatory.

Local

Documents, extraction, retrieval, memory, storage and models can remain in the private environment when the chosen stack supports it.

Hybrid

Sensitive data stays local while selected external capabilities are called explicitly and within a bounded scope.

Cloud

Hosted services can be used when appropriate. Their availability does not make them necessary for every dossier.
