Understand · no prerequisites

Between your question and the answer, what is AI actually doing?

On screen, everything feels immediate. Behind the answer, the system has to receive context, retrieve the right passages, sometimes remember, sometimes act — and then we still need to know what the result is worth. This page follows that path without unnecessary jargon.

Pantheon is not another AI.

It keeps the work readable when sources, versions, responsibilities and decisions start to matter.

The map before the details

The essentials fit into six ideas.

The technical vocabulary becomes much simpler once every term has a clear job.

01 · Produce

The model

The engine that composes the answer.

It writes, compares, analyses or reasons from what it is given. It does not automatically have your entire dossier in view.

02 · Make available

Context

What is on the desk right now.

The question, instructions, document excerpts, tool results or useful memories: this is the material available for the task.

03 · Retrieve

RAG

Search before answering.

It looks through the sources for a few useful passages and brings them to the model when they are needed.

04 · Continue

Memory

What prevents every task from starting at zero.

It carries continuity through time. But a memory still belongs to a dossier, a date and a status.

05 · Do

The executor

The part that carries out the mission.

It mobilizes models, tools and reusable know-how, works through several steps and returns a result.

06 · Keep the frame

Pantheon

What keeps the path reviewable.

Mission, scope, sources, capabilities, provenance, evidence, statuses and decisions do not dissolve into a single polished answer.

1 · Retrieve

AI answers with what it actually has in front of it.

A model may be excellent and still miss the decisive exhibit. The job is therefore to prepare the context and retrieve the right material without dropping an entire library into every request.

Context

The working desk.

Too empty, and a key piece is missing. Too full, and it becomes noisy. Good context contains what the mission needs — not the rest of the world, and not only the last line of the chat.

Tokens

The units a model handles.

Text is broken into small units, and the amount a model can inspect at once remains finite. That is one reason useful passages are selected.

The chunk

A piece that keeps its address.

A long document is prepared as searchable passages. Each piece stays linked to its document, page, section and, whenever possible, the version it came from.

The embedding

A mathematical representation of semantic proximity.

It helps bring together different wordings that are nevertheless about the same idea.

Why combine exact search and semantic search?

An index, reference or exact name is often easy to find by words. The same idea expressed differently may be easier to retrieve by semantic proximity. Hybrid retrieval combines both and then ranks the results.

That ranking helps the search. It does not give the top passage any special authority.

What might be retrieved in LIA21?

The ventilation question may bring back a specification, a meeting note and an inspection record. The model can use them to draft a reply; we still need to know which piece is newer, which revision applies and what each one actually supports.

2 · Organize

Memory is only useful if we know what it belongs to, where it came from and when it was true.

One giant memory eventually mixes projects, experiments and old assumptions. Continuity becomes useful when it stays classified, dated and reversible.

Three working-memory domains

A

Agency

What deserves to be reused.

Methods, references, templates, working habits and lessons that outlive one particular dossier.

P

Projects

What belongs to one case.

Meetings, hypotheses, decisions, drafts, exchanges and context that belong to LIA21, SOL14 or another dossier.

S

Sandbox

What can be tested without contaminating reality.

Synthetic data, new models, new versions and experimental integrations stay isolated from professional dossiers.

These domains organize working memory. They do not replace task scope, information status or navigation categories. A note can remain a note; a durable decision should still lead back to its source.

Classify so retrieval does not become mixing

This lets the system search LIA21 without silently letting SOL14 leak into the answer. Categories and tags may help navigation, but they remain classification aids, not evidence or authorization.

Versions: keep the history without mistaking old for current

Keep the trace

An older revision may explain why a decision was made. Deleting it would erase part of the history.

Recover the applicable state

Index, date, active revision, supersession and obsolescence need to remain visible so an old passage does not quietly return as the current state.

Why Markdown?

A Markdown file, usually ending in .md, is simply plain text with a few marks for headings, lists and links.

# LIA21 — 14 August meeting

## Ventilation
The inspection still needs confirmation.

- expected source
- contractor reply pending

It remains readable without specialist software, easy to compare across versions, easy to search and practical for both people and AI tools. Most importantly, it is portable: the content does not depend on one application to remain understandable.

The format does not change the authority of the source. A received PDF remains the received PDF. Markdown produced from that PDF is a working representation that should continue to point back to the original.

M
Good memory does not merely ask “what looks similar?” It searches in the right place, by the right method, then checks whether what it found still applies.

In the candidate model, this is Mnemosyne’s territory. She directs retrieval toward the right domain or dossier, chooses the appropriate search strategy, watches for duplicates, indices, dates, versions and superseded records. The executor performs the retrieval; Mnemosyne keeps the memory discipline.

Memory · candidate model

Where should we look?

Active project, Agency memory, Sandbox, working corpus, qualified sources or the Register: scope comes before the search engine.

Retrieval · candidate model

How should we look?

Exact words, semantic proximity, chronology and relations between items can be combined. The question chooses the method, not the other way round.

Continuity · candidate model

What should be kept, and where?

Mnemosyne may propose: session, Project, Agency, Sandbox, archive or Register Candidate. A proposed destination never promotes an item by itself.

The current canonical Role registry does not yet include Mnemosyne. Her memory responsibility exists in the candidate model and visual language; any canonization must therefore converge explicitly with the existing schemas and registries before becoming a system rule.

What about conversational memory?

It can make an assistant more convenient by preserving preferences or continuity. For governed work, its injection may be restricted or disabled so the result rests on explicit context rather than invisible recall.

3 · Act

An answer becomes something else as soon as it can create an effect.

Opening a file, searching the Web, calling an API, modifying a document or preparing a message is no longer just conversation. We need to separate what knows, what knows how and what actually executes.

The tool

A concrete capability.

Read, search, calculate, export, call a service or write somewhere.

The skill

A way of doing the job well.

The tool opens the PDF; the skill describes how to review it, what to check and how to present the result.

The agent

An objective rather than one answer.

It can observe, choose a step, use a tool, inspect the return and continue until the expected result is reached.

The executor

The engine that actually performs the work.

An agent runtime or external service receives a bounded mission. Pantheon should be able to change executors without changing its own responsibility.

The run

This execution, here and now.

Running the same task tomorrow creates another run, with its own events, tool calls and results.

The workflow

The repeatable method.

It describes a path through the work. The executor that follows that path remains a separate responsibility.

API, connector, MCP: three words for three different layers

An API lets two software systems communicate in a structured way. A connector adapts one particular service. MCP provides a common convention for exposing tools and resources to AI systems.

These mechanisms make connections easier; they do not decide by themselves whether a capability is permitted in this mission.

Task, session, run: the simplest distinction

The task says what must be accomplished. The session keeps the thread of an interaction. The run is one concrete execution. A session can therefore contain several tasks and several runs.

4 · What can count

Producing an answer is easy. Knowing what that answer permits is a different problem.

In LIA21, one sentence says the ventilation is compliant. The model can turn that into an excellent email. The dossier still asks: which exhibit, which date, which index, which scope, which inspection?

?
Which document? Which revision? Who is speaking? Is there a newer piece? Is this a statement, an observation or an approval?

Pantheon keeps that path readable: not to declare truth instead of the professional, but to stop a conclusion from losing the conditions it came from.

The mission sheet

What is asked, permitted and expected.

The Task Contract can state intent, scope, constraints, useful Pantheon viewpoints, approvals, expected evidence, allowed or forbidden outputs and memory rules.

The execution green light

This exact mission may start.

Execution Admission checks the launch conditions. It says neither that the run has already happened nor that its future result will be valid.

Provenance

Being able to walk back to the origin.

Document, email, Web, memory, calculation, tool or person: the conclusion keeps the path back to the actual material.

The candidate result

A result whose status has not changed yet.

The runtime may have completed its work perfectly while the content remains a draft to verify, discuss or approve.

The evidence item

One piece supporting one bounded point.

An Evidence Item links a claim to a source, a locator and an explicit support scope.

The Evidence Pack

The review file for the result.

It gathers what makes the path understandable: sources, evidence items, assumptions, actions, risks, outputs, reviews and approval state.

The Register Candidate

What we are considering keeping durably.

Before the Probative Register, an item can remain a candidate with its scope, provenance, certainty, risk and outstanding validations.

The Probative Register

What remains with the reasons it may be relied on.

It keeps qualified, sourced, reviewable assertions. It is not simply a larger collection of things the assistant remembers.

The question for the human

Make the missing decision visible.

When an arbitration is required, Pantheon can present the question, options, missing material and blocked action. The decision request remains distinct from the decision itself.

Why not use one single “reliability” score?

Because four different questions would be crushed into one number: what evidence do we have? what has actually been verified? what are the consequences? who still needs to approve?

E · Certainty

How much probative support does the claim have?

V · Verification

What has actually been checked or observed?

K · Consequence

What could happen if we act or conclude on this basis?

C · Approval

What level of decision is still required?

The technical codes E0–E4, V0–V4, K0–K4 and C0–C5 then make those axes comparable without mixing them.

Roles bring viewpoints. Rites bring method when a difficulty recurs. Spaces stop contexts from collapsing into one another. The executor does the work. Humans retain decisions that carry consequences.

The mythology is a mental shortcut. It is not a cast of autonomous little agents performing a play inside Pantheon.

The seven canonical Roles: seven angles of judgment

They are not all invoked. A mission names only the viewpoints that can genuinely improve the result.

Structure · ATHENA

Athena puts the problem back in order.

She clarifies the goal, breaks down what needs breaking down and notices when a request is expanding without limits.

She becomes useful when several objectives, phases or decisions are tangled together.

Sources · ARGOS

Argos asks what we are relying on.

He examines provenance, source quality, missing exhibits and contradictions that weaken a claim.

His viewpoint matters whenever we need to show where a statement came from.

Boundaries · THEMIS

Themis looks at how far we may go.

Mission, risk, rule, responsibility and approval level: she makes boundaries visible before they are crossed.

She is valuable before an external action or a consequential conclusion.

Quality · APOLLO

Apollo rereads what already looks finished.

He looks for gaps hidden by polished wording: clarity, completeness, sufficient support and readiness to present.

This is the final-review viewpoint before a draft starts looking too much like a deliverable.

Fabrication · HEPHAISTOS

Hephaistos prepares what needs to be built.

He qualifies the structure of a document, export, patch or other artifact candidate. The executor then performs the admitted production.

He intervenes when an intention must become something concrete without confusing fabrication with validation.

Transmission · IRIS

Iris looks at what is about to cross the threshold.

Recipient, channel, wording, ambiguity and effect: she works on transmission without rewriting the underlying decision.

Her viewpoint matters before something is sent, especially when tone, confidentiality or responsibility matter.

Arbitration · ZEUS

Zeus qualifies the next procedure.

Faced with conflict or variants, he may keep the work as draft, request another exhibit, narrow scope, block a transition or return the choice to a human.

He intervenes when the next move itself needs a decision. He does not decree truth.

The Task Contract connects these viewpoints to a real mission. It can name an owner Role and a few useful perspectives instead of activating the whole college by reflex.

Mnemosyne: a memory responsibility that is still candidate

M
Argos asks: “how strong is this source?” Mnemosyne asks: “where in our history should we look, which version matters now, and what is worth keeping?”

The candidate model gives her continuity: history, earlier meeting notes, prior decisions, duplicates, latest-known state, memory placement and prudence before promotion. She can direct retrieval by scope, exact terms, meaning, chronology or relations, then check indices, dates and versions before reuse. The executor performs the retrieval; Mnemosyne governs its memory logic.

She may propose that an item remain in the session, join the Project, be extracted toward Agency memory, stay in Sandbox, be archived or become a Register Candidate. She never turns a memory into a validated reference by herself. This function is documented as candidate; the canonical Role registry and schemas must be explicitly converged before it can be presented as an established eighth Role.

Where does Hermes fit?

Hermes Agent is a candidate on the execution side: an external runtime can receive a bounded mission, mobilize the required capabilities and return a run result. It may use a profile aligned with a Pantheon viewpoint without inheriting that viewpoint’s governance authority.

Rites: when a precise method is better than one more answer

A rite is a temporary review procedure. It handles a recognizable difficulty; it is neither automatic nor required for every request.

Controlled divergence

The team settled on one path too quickly.

Open several possibilities before criticizing them and converging.

Contradictory self-review

The first result is too convincing to trust without resistance.

Review it as if it came from someone else, actively looking for weaknesses, omissions and contradictions.

Source concordance

Several exhibits discuss the same point without telling quite the same story.

Compare their dates, scopes, actual support and contradictions before relying on them.

Hidden premises

A reasoning chain stands up because of assumptions nobody has stated.

Make those assumptions visible before they quietly become constraints.

Session refoundation

The thread has become too long, too mixed or too burdened with old assumptions.

Restart from a clean bounded context instead of piling on more material.

And sometimes: no rite.

A simple task deserves to stay simple.

Governance is useful only when it materially improves the decision, evidence or control of risk.

Spaces: stop something from counting in the wrong place

Spaces are governance distinctions, not necessarily folders or screens. They separate what should endure as a rule, what belongs only to a project and what still needs deliberation.

They differ from Agency / Projects / Sandbox. Those organize working memory; the Spaces below describe the context in which an activity or decision has meaning.

Reusable

Governance Reference Space

Rules, methods, statuses and principles meant to outlive one dossier.

It prevents a habit from LIA21 from quietly becoming a general rule.

Bounded

Project Space

Sources, constraints, decisions, evidence candidates and context that belong to one defined case.

It keeps LIA21 separate from SOL14 when several dossiers coexist.

Deliberation

Agora

The conceptual place where positions and what the sources can no longer settle are made visible.

It becomes useful for professional preference, a choice between legitimate variants or disagreement that requires a human decision.

Does all of this already exist as machine schemas?

Not uniformly, and the page makes that visible on purpose. Task Contracts, Role Signals, Evidence Packs, Register Candidates and several other objects already have validation contracts. Rites and governed Spaces remain primarily documented governance grammar rather than being forced into technical objects everywhere.

Technology candidates

Functions should outlive products.

The names below are candidates being studied today. They do not define the architecture and may be replaced.

Agent execution

Hermes Agent is being studied as the main candidate for external execution: receive a bounded mission, mobilize models, skills and tools, then return the run result.

candidate · replaceable

Notes and workspace

Obsidian is qualified as a candidate for local Markdown notes and human-readable organization. The files remain usable outside the application.

qualified candidate · bounded scope

Associative memory

Hindsight is the first qualified candidate for associative working memory derived from notes. It helps recall and connect material; it does not give professional status to what it retrieves.

qualified candidate · bounded use

Memory alternative

TencentDB Agent Memory has been evaluated. The tested topology raised state-consistency and identity-isolation concerns, so activation is deferred and may be revisited.

evaluated · deferred

Document analysis

Docling is the preferred candidate for extracting usable document structure: headings, paragraphs, tables, reading order and source-linked derivatives. Runtime integration remains a separate qualification question.

preferred candidate · integration to qualify

Data and privacy

Cloud is not an architectural requirement.

The chain can remain local when the selected components support it.

Documents, Markdown notes, extraction, retrieval, associative memory, databases and models can run on a computer, private server or suitable NAS.

Cloud remains available when an external capability is useful and accepted. Web search, a hosted model or a third-party API then crosses the local boundary explicitly.

The useful question is not “all local” versus “all cloud”. It is knowing, capability by capability, where the data goes and why.

Local

The stack stays inside the private environment when the selected models and services allow it.

Hybrid

Sensitive data remains local while a few external capabilities are called explicitly and within a bounded scope.

Cloud

Hosted services may be chosen when they provide the right capability. Their availability does not make them mandatory.
